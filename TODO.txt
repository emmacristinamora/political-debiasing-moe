1. Read config and arguments.

You pass --source allsides and --config-yaml-path config/config.yaml. The script reads chunking parameters, thresholds, pooling settings, topic prototypes, and all file paths from the config. Every value has a CLI override, but nothing is hardcoded in the script itself.

2. Load the base model and tokenizer.

Mistral-7B is loaded in float16 onto the target device. output_hidden_states=True is set so every forward pass returns the full stack of hidden states, not just the final logits. The model is set to eval mode — no gradients, no dropout.

3. Load the two steering vectors.

Two separate .pt files are loaded — one for the economic axis, one for the social axis. From each file the script extracts final_vectors["logistic_regression"], which is the quality-weighted aggregate of the per-layer logistic regression vectors computed in script 04. Both are re-normalized to unit norm.

4. Embed the topic prototypes.

Each of the 9 topic prototype texts (economy, immigration, foreign policy, …) is run through the model once and stored as a normalized embedding. This happens at startup, once, before any documents are processed.

5. Stream documents from the normalized JSONL.

The script opens one file from data/experts/raw/normalized/ — the one matching the --source argument. It reads it line by line, normalizes whitespace on each text field, and yields RawDocument objects. The canonical schema fields (source_name, source_family, metadata, etc.) are read directly from each row — nothing is inferred or overridden from CLI.

6. For each document: chunk it.

The document text is split into overlapping token windows. With the defaults: window of 512 tokens, 128-token overlap, 384-token step. Windows shorter than 128 tokens are discarded. A document of 600 tokens produces two chunks; one of 2000 tokens produces five or six.

7. For each chunk: encode it.

The chunk text is tokenized and run through the model. The hidden state at the configured layer (default: last layer) is mean-pooled over non-padding tokens, then normalized to unit norm. The result is a single vector h in the model's representation space.

8. For each chunk: project onto the two steering axes.

Two dot products:

score_econ = h · v_econ — positive means economically right, negative means economically left
score_soc = h · v_soc — positive means authoritarian, negative means libertarian
Both are cosine similarities because both vectors are unit-normalized. A confidence_margin is computed as min(|score_econ|, |score_soc|) — how far the chunk sits from both axes simultaneously.

9. For each chunk: assign a quadrant and check thresholds.

The sign of the two scores gives the quadrant (q1 = left-libertarian, q2 = left-authoritarian, q3 = right-libertarian, q4 = right-authoritarian). The chunk passes the threshold if |score_econ|, |score_soc|, and confidence_margin all exceed the configured minimums. Chunks that don't pass are still recorded — marked selection_stage = "scored" — but not labeled or retained.

10. For retained chunks only: assign a topic label.

The chunk embedding h is compared against each of the 9 pre-embedded topic prototypes by cosine similarity. The highest-scoring topic becomes topic_primary, the second-highest becomes topic_secondary. This runs only on retained chunks — there is no point topic-labeling a chunk that will never enter a quadrant pool.

11. Write all scored chunks and document summaries.

Every chunk — retained or not — is written to scored_chunks.jsonl. This is the audit file: you can load it later to inspect score distributions, tune thresholds, or understand what was filtered out. A per-document summary (mean/std scores, dominant quadrant, chunk counts) is written to document_summaries.jsonl.

12. Write retained pools and reports, per quadrant.

Retained chunks are grouped by quadrant. For each of q1–q4, the script writes:

retained.jsonl — the actual pool of chunks that passed thresholds
report.json — volume, source composition, topic composition, source×topic breakdown, and the 5 highest-confidence examples
13. Output lands in a per-source directory.

Everything goes to data/experts/quadrant_pools/{source}/. Running the script on allsides and then on hoc produces two separate directory trees that don't overwrite each other.
